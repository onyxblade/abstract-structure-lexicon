## 物理排列取捨

一句話：只要資料必須被實體排列，就不可能同時讓所有訪問模式都成為局部的；最佳化一種 access pattern 會讓另一種變昂貴。

結構：

```text
同一份資料
→ 必須選一種主要物理排列
→ 某些操作變 local / sequential / cheap
→ 另一些操作變 scattered / reconstructed / expensive
→ no silver bullet
```

核心張力：

```text
物理局部性只能服務某些關係
讓 A 靠近 B，往往就是讓 A 遠離 C
```

補償方式：

```text
hybrid / index / materialized view / cache / duplicated storage
→ 緩解查詢成本
→ 轉移為儲存、寫入、同步、一致性複雜度
```

例子：

- 行式資料庫：讀一筆完整 record 便宜；掃描單一欄位昂貴
- 列式資料庫：掃描/聚合單一欄位便宜；重建完整 record 較昂貴
- Array of Structs vs Struct of Arrays：物件局部性 vs 欄位批量處理
- 筆記分類：放在某個資料夾會強化一種脈絡，同時削弱其他脈絡
- 組織設計：把人按功能部門靠近，會讓產品/任務脈絡變遠；反之亦然

相近概念：no silver bullet, representation-workload fit, locality, trade-off, data layout, access pattern, CAP-like constraint
